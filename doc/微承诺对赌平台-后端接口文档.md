# 微承诺对赌平台 · 后端接口文档

> 版本：v1.0（7 天 MVP 版）
> 技术栈：SpringBoot 3.x + MyBatis-Plus + MySQL 8 + Redis + Sa-Token（认证）
> 适用范围：三人小组并行开发的接口契约，前后端以本文档为准

---

## 1. 通用约定

### 1.1 基础信息

| 项 | 值 |
| --- | --- |
| 基础路径 | `/api` |
| 请求/响应格式 | `application/json; charset=UTF-8` |
| 鉴权方式 | 请求头 `Authorization: Bearer {token}` |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（字符串） |
| 金额单位 | 虚拟币，整数，无小数 |

### 1.2 统一响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

| code | 含义 |
| --- | --- |
| 0 | 成功 |
| 400 | 参数校验失败 |
| 401 | 未登录或 token 失效 |
| 403 | 无权限（如非见证人投票） |
| 404 | 资源不存在 |
| 409 | 状态冲突（如重复投票、重复结算、余额不足） |
| 500 | 服务器内部错误 |

### 1.3 分页请求/响应约定

请求参数（Query）：`page`（从 1 开始，默认 1）、`size`（默认 10，最大 50）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 32,
    "page": 1,
    "size": 10,
    "records": []
  }
}
```

### 1.4 核心枚举

**合约状态 `ContractStatus`**

| 值 | 含义 | 说明 |
| --- | --- | --- |
| ACTIVE | 进行中 | 创建后初始状态，押金已冻结 |
| VOTING | 待裁决 | 到期后由定时任务自动流转，等待见证人投票 |
| SUCCESS | 已完成 | 裁决通过，押金解冻退还 |
| FAILED | 已违约 | 裁决未通过或到期无人投票，押金扣除 |

**投票选项 `Verdict`**：`SUCCESS`（完成）/ `FAIL`（未完成）

**流水类型 `TransactionType`**

| 值 | 含义 |
| --- | --- |
| GIFT | 注册赠送 |
| FREEZE | 创建合约冻结押金 |
| UNFREEZE | 履约成功解冻退还 |
| DEDUCT | 违约扣除押金 |

**结算规则（写死，二期再扩展）**

- 见证人多数决：SUCCESS 票 > FAIL 票 → 合约 SUCCESS；否则 FAILED（平票算失败）
- VOTING 状态超过 24 小时无人投票 → 自动 FAILED
- SUCCESS：解冻押金退回余额，履约数 +1
- FAILED：扣除押金（进入平台池，仅记账），跳票数 +1

## 2. 认证与用户模块

> 实现约定：认证统一使用 **Sa-Token**，不引入 Spring Security。
> >
> - 依赖：`sa-token-spring-boot3-starter` + `sa-token-redis`（token 会话自动存 Redis，无需自行维护）
> - 登录：`StpUtil.login(userId)`，登出：`StpUtil.logout()`，取当前用户：`StpUtil.getLoginIdAsLong()`
> - 登录拦截：`SaInterceptor` 全局校验，放行 `/api/auth/login`、`/api/auth/register` 及广场公开接口
> - 密码加密仍由业务层负责（BCrypt），Sa-Token 只管会话不管密码
> - 前端请求头沿用 `Authorization: Bearer {token}`，token 值为 `StpUtil.getTokenValue()`

### 2.1 注册

`POST /api/auth/register`（无需鉴权）

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 4~20 位，唯一 |
| password | string | 是 | 6~20 位 |
| nickname | string | 是 | 昵称 |

响应 `data`：

```json
{
  "userId": 10001,
  "token": "eyJhbGciOi...",
  "giftAmount": 1000
}
```

说明：注册成功自动赠送 1000 虚拟币（记一笔 GIFT 流水），并直接返回 token 免二次登录。

### 2.2 登录

`POST /api/auth/login`（无需鉴权）

```json
{ "username": "zhangsan", "password": "123456" }
```

响应 `data`：

```json
{
  "userId": 10001,
  "nickname": "张三",
  "token": "eyJhbGciOi...",
  "balance": 1000,
  "frozen": 0
}
```

### 2.3 登出

`POST /api/auth/logout`

说明：调用 `StpUtil.logout()`，Sa-Token 自动清除 Redis 中的会话。响应 `data` 为 `null`。

### 2.4 当前用户信息

`GET /api/auth/profile`

响应 `data`：

```json
{
  "userId": 10001,
  "username": "zhangsan",
  "nickname": "张三",
  "avatar": null,
  "balance": 800,
  "frozen": 200,
  "createdAt": "2026-11-20 10:00:00"
}
```

## 3. 合约模块

### 3.1 创建对赌合约

`POST /api/contracts`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| title | string | 是 | 目标标题，如"30 天背完 1000 个单词"，≤50 字 |
| description | string | 否 | 目标描述/验收标准，≤500 字 |
| category | string | 否 | 分类：STUDY 学习 / FITNESS 健身 / LIFE 生活 / OTHER 其他 |
| deadline | string | 是 | 截止时间，必须晚于当前时间；演示模式下允许 1 分钟后 |
| deposit | int | 是 | 押金，1 ~ 当前可用余额 |

业务规则：

- 创建时校验余额并**冻结押金**（FREEZE 流水 + 事务）
- 创建后状态为 ACTIVE，广场立即可见

响应 `data`：合约详情（结构同 3.3）

失败：`409` 余额不足 / `400` 截止时间不合法

### 3.2 我的合约列表

`GET /api/contracts/my?status=ACTIVE&page=1&size=10`

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| status | 否 | 按状态筛选，不传查全部 |
| page / size | 否 | 分页 |

响应 `data.records[]`：

```json
{
  "contractId": 20001,
  "title": "30 天背完 1000 个单词",
  "category": "STUDY",
  "status": "ACTIVE",
  "deposit": 200,
  "deadline": "2026-12-20 23:59:59",
  "createdAt": "2026-11-20 10:00:00",
  "witnessCount": 2
}
```

### 3.3 合约详情

`GET /api/contracts/{contractId}`

响应 `data`：

```json
{
  "contractId": 20001,
  "title": "30 天背完 1000 个单词",
  "description": "每天 35 个，墨墨背单词打卡截图为准",
  "category": "STUDY",
  "status": "VOTING",
  "deposit": 200,
  "deadline": "2026-12-20 23:59:59",
  "createdAt": "2026-11-20 10:00:00",
  "settledAt": null,
  "owner": { "userId": 10001, "nickname": "张三" },
  "witnesses": [
    { "userId": 10002, "nickname": "李四", "vote": "SUCCESS", "votedAt": "2026-12-21 09:00:00" },
    { "userId": 10003, "nickname": "王五", "vote": null, "votedAt": null }
  ],
  "proof": {
    "content": "已完成，附 30 天打卡截图",
    "images": ["https://xxx/proof1.png"],
    "submittedAt": "2026-12-20 20:00:00"
  },
  "settleResult": null,
  "viewCount": 56
}
```

权限：任何登录用户可看（广场公开）；witnesses 的 vote 字段在合约完结前对非本人脱敏（返回 null），防止跟风投票。

### 3.4 生成见证人邀请链接

`POST /api/contracts/{contractId}/witness-invite`

权限：仅合约创建者；仅 ACTIVE 状态。

响应 `data`：

```json
{
  "inviteCode": "a8f3k2",
  "inviteUrl": "https://your-domain.com/witness/accept/a8f3k2",
  "expireHours": 72
}
```

说明：inviteCode 存 Redis，TTL 72 小时；同一合约重复调用返回同一个有效码。

### 3.5 接受见证邀请

`POST /api/witness-invites/{inviteCode}/accept`

业务规则：

- 不能见证自己的合约（`409`）
- 同一合约最多 5 名见证人
- 接受后写入合约-见证人关联表

响应 `data`：

```json
{ "contractId": 20001, "contractTitle": "30 天背完 1000 个单词" }
```

### 3.6 提交履约凭证（可选流程）

`POST /api/contracts/{contractId}/proof`

权限：仅创建者；ACTIVE 或 VOTING 状态均可提交/覆盖。

```json
{
  "content": "已完成，附打卡截图",
  "images": ["https://xxx/proof1.png"]
}
```

说明：凭证仅作展示，供见证人投票参考，不影响状态流转。

## 4. 裁决模块

### 4.1 我的待裁决列表

`GET /api/verdicts/pending?page=1&size=10`

说明：返回"我作为见证人、状态为 VOTING、且我尚未投票"的合约，含合约摘要与凭证。用于前端红点和工作台。

响应 `data.records[]`：

```json
{
  "contractId": 20001,
  "title": "30 天背完 1000 个单词",
  "owner": { "nickname": "张三" },
  "deposit": 200,
  "deadline": "2026-12-20 23:59:59",
  "votingStartedAt": "2026-12-21 00:00:05"
}
```

### 4.2 见证人投票

`POST /api/contracts/{contractId}/vote`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| verdict | string | 是 | SUCCESS / FAIL |
| comment | string | 否 | 评语，≤200 字 |

业务规则：

- 仅该合约见证人可投（`403`）；仅 VOTING 状态（`409`）
- 一人一票，不可改票；用 Redis `SETNX` 做幂等防重复提交
- 投票后立即计票：若已产生多数决结果（SUCCESS 票 > FAIL 票，或 FAIL 票 ≥ SUCCESS 票且全员已投），触发结算；全员投完必结算

响应 `data`：

```json
{
  "voted": true,
  "currentVotes": { "success": 2, "fail": 0, "total": 3 },
  "settled": false
}
```

### 4.3 查看投票结果

`GET /api/contracts/{contractId}/votes`

响应 `data`：

```json
{
  "success": 2,
  "fail": 1,
  "total": 3,
  "result": "SUCCESS",
  "detail": [
    { "nickname": "李四", "verdict": "SUCCESS", "comment": "每天坚持打卡，佩服", "votedAt": "2026-12-21 09:00:00" }
  ]
}
```

说明：合约完结后公开投票明细；未完结时 detail 仅返回计票数字。

## 10. 定时任务与 Redis 使用说明（后端内部约定）

### 10.1 定时任务

| 任务 | 频率 | 逻辑 |
| --- | --- | --- |
| 到期扫描 | 每 30 秒 | ACTIVE 且 deadline < now → VOTING，给见证人发裁决通知 |
| 超时裁决 | 每 5 分钟 | VOTING 超过 24 小时 → FAILED 结算 |
| 围观数落库 | 每 10 分钟 | Redis viewCount 增量写入 MySQL |

### 10.2 Redis Key 约定

| Key | 类型 | 用途 |
| --- | --- | --- |
| 登录会话 | 由 Sa-Token 托管 | `sa-token-redis` 自动读写，TTL 与续期在 `application.yml` 的 `sa-token` 配置中设置，业务代码不直接操作 |
| `contract:settle:lock:{contractId}` | String | 结算分布式锁（SETNX + TTL 10s），防并发重复结算 |
| `vote:idem:{contractId}:{userId}` | String | 投票幂等键 |
| `contract:invite:{inviteCode}` | String | 邀请码 → contractId，TTL 72h |
| `square:view:{contractId}` | String | 围观计数 |
| `square:view:limit:{contractId}:{userId}` | String | 围观去重，TTL 1h |

### 10.3 结算事务约定（重点）

结算必须在**单个数据库事务**内完成：

1. 获取 Redis 结算锁，拿不到直接返回（另一节点在处理）
2. `SELECT ... FOR UPDATE` 锁定合约行，校验状态仍为 VOTING
3. 按结果写流水（UNFREEZE 或 DEDUCT）、更新用户余额/冻结金额
4. 更新合约状态、settledAt、settleResult
5. 更新双方履约统计
6. 提交事务后释放锁、发通知

## 12. 实体类设计

> 技术栈配套：MyBatis-Plus + Lombok。字段与《数据库设计文档》一一对应。

### 12.1 分包结构建议

```javascript
com.example.bet
├── common
│   ├── entity/BaseEntity.java        # 公共字段基类
│   ├── enums/                        # 全部枚举
│   └── result/R.java                 # 统一返回体
├── module
│   ├── user/                         # 乙
│   │   ├── entity/SysUser.java
│   │   ├── dto/                      # 注册、登录请求
│   │   └── vo/                       # 用户信息、诚信档案
│   ├── contract/                     # 甲
│   │   ├── entity/BetContract.java
│   │   ├── entity/BetContractWitness.java
│   │   ├── dto/                      # 创建合约、提交凭证请求
│   │   └── vo/                       # 合约列表项、合约详情
│   ├── verdict/                      # 乙
│   │   ├── entity/BetVote.java
│   │   └── dto/VoteRequest.java
│   ├── account/                      # 甲
│   │   ├── entity/AccTransaction.java
│   │   └── vo/                       # 余额、流水
│   └── notice/                       # 乙
│       └── entity/SysNotification.java
```

约定：**Entity 只对应表，绝不出现在 Controller 返回值里**；入参用 DTO、出参用 VO，避免把 `password` 这类字段泄露给前端。

### 12.2 公共基类与统一返回体

**BaseEntity**

```java
@Data
public abstract class BaseEntity {

    @TableId(type = IdType.AUTO)
    private Long id;

    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createdAt;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updatedAt;
}
```

> `created_at` / `updated_at` 已由数据库 `DEFAULT CURRENT_TIMESTAMP` 兜底，若不想写 `MetaObjectHandler`，可直接去掉这两个 fill 注解、只保留字段映射。
> `is_deleted` 不放在基类里（投票表、通知表没有该字段），需要的表自行声明。

**统一返回体 R**

```java
@Data
@AllArgsConstructor
public class R<T> {
    private Integer code;
    private String message;
    private T data;

    public static <T> R<T> ok(T data) { return new R<>(0, "success", data); }
    public static R<Void> ok()        { return new R<>(0, "success", null); }
    public static R<Void> fail(int code, String msg) { return new R<>(code, msg, null); }
}
```

### 12.3 枚举设计

```java
/** 合约状态 */
public enum ContractStatus {
    ACTIVE,   // 进行中
    VOTING,   // 待裁决
    SUCCESS,  // 已完成
    FAILED    // 已违约
}

/** 投票选项 */
public enum Verdict {
    SUCCESS, FAIL
}

/** 合约分类 */
public enum ContractCategory {
    STUDY, FITNESS, LIFE, OTHER
}

/** 流水类型 */
public enum TransactionType {
    GIFT,      // 注册赠送
    FREEZE,    // 冻结押金
    UNFREEZE,  // 解冻退还
    DEDUCT     // 违约扣除
}

/** 通知类型 */
public enum NotificationType {
    WITNESS_INVITE,     // 见证邀请
    WITNESS_ACCEPTED,   // 见证人已接受
    VERDICT_REQUEST,    // 裁决请求
    CONTRACT_SETTLED    // 结算结果
}
```

### 12.7 落地注意事项

1. **Entity 不出 Controller**：尤其是 `SysUser.password`，已加 `@JsonIgnore` 双保险，但规范上仍要求返回 VO
2. **金额字段全部 `Integer`**：不要在任何环节引入 `double`/`float`；履约率用 `BigDecimal`，`setScale(2, RoundingMode.HALF_UP)`
3. **时间统一 `LocalDateTime`**：全局 Jackson 配置 `yyyy-MM-dd HH:mm:ss` 序列化格式，与接口文档 1.1 对齐
4. **Lombok 必用**：`@Data` + 需要时 `@Builder`，7 天排期不手写 getter/setter
5. **DTO 校验靠注解**：`@NotBlank/@Future/@Min` 能挡掉的脏数据，不要留到 Service 里手写 if
6. **枚举直接映射**：MyBatis-Plus 默认按 `name()` 存取，不要自定义 ordinal 存储，避免顺序变动出事故
