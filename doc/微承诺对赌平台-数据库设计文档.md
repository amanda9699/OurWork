# 微承诺对赌平台 · 数据库设计文档

> 版本：v1.0（7 天 MVP 版）
> 技术栈：SpringBoot 3.x + Vue 3 + MyBatis（建议 MyBatis-Plus）+ MySQL 8.0 + Redis
> 配套文档：《微承诺对赌平台-后端接口文档.md》（本文档字段与接口文档一一对应）

---

## 1. 设计总览

### 1.1 表清单

| 表名 | 说明 | 数据量级（演示） |
|---|---|---|
| `sys_user` | 用户表，含余额与冻结金额 | 十级 |
| `bet_contract` | 对赌合约表（核心表） | 十级 |
| `bet_contract_witness` | 合约-见证人关联表 | 十级 |
| `bet_vote` | 见证人投票表 | 十级 |
| `acc_transaction` | 资金流水表（只增不改） | 百级 |
| `sys_notification` | 站内通知表 | 百级 |

共 6 张表。见证邀请码、登录会话、围观计数、分布式锁均放 Redis，不落库（见接口文档第 10 章）。

### 1.2 核心关系（ER 简述）

```
sys_user 1 ── n bet_contract            （一个用户可发起多个合约）
bet_contract 1 ── n bet_contract_witness（一个合约最多 5 名见证人）
sys_user 1 ── n bet_contract_witness    （一个用户可见证多个合约）
bet_contract 1 ── n bet_vote            （一个合约对应多张选票）
bet_vote n ── 1 bet_contract_witness    （每张选票属于一名见证人）
sys_user 1 ── n acc_transaction         （资金流水按用户归档）
bet_contract 1 ── n acc_transaction     （冻结/解冻/扣款均关联合约）
sys_user 1 ── n sys_notification        （通知按接收人归档）
```

### 1.3 全局约定

- 字符集：`utf8mb4` / `utf8mb4_unicode_ci`
- 主键：`BIGINT UNSIGNED AUTO_INCREMENT`
- 时间字段：`DATETIME`，统一 `created_at` / `updated_at`
- 金额：虚拟币整数，`INT`，单位"币"，无小数
- 逻辑删除：MVP 不做物理删除以外的需求，统一 `is_deleted TINYINT` 字段（MyBatis-Plus 可直接配置逻辑删除）
- 命名：表名模块前缀（`sys_` 系统、`bet_` 合约、`acc_` 账务），字段下划线

## 2. 表结构详述

### 2.1 sys_user 用户表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK | 用户 ID |
| username | VARCHAR(20) | NOT NULL, UNIQUE | 登录名，4~20 位 |
| password | VARCHAR(100) | NOT NULL | BCrypt 加密存储，严禁明文 |
| nickname | VARCHAR(30) | NOT NULL | 昵称 |
| avatar | VARCHAR(255) | NULL | 头像 URL，MVP 可空 |
| balance | INT | NOT NULL DEFAULT 1000 | 可用余额，注册送 1000 |
| frozen | INT | NOT NULL DEFAULT 0 | 冻结金额（进行中合约押金之和） |
| is_deleted | TINYINT | NOT NULL DEFAULT 0 | 逻辑删除 |
| created_at | DATETIME | NOT NULL | 注册时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

设计说明：

- `balance + frozen` 为该用户总资产；所有变动必须同时写 `acc_transaction` 流水
- 余额更新必须使用**带条件的原子 UPDATE**（见 4.2），禁止"先查后改"

### 2.2 bet_contract 对赌合约表（核心表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK | 合约 ID |
| user_id | BIGINT UNSIGNED | NOT NULL | 创建者 ID |
| title | VARCHAR(50) | NOT NULL | 目标标题 |
| description | VARCHAR(500) | NULL | 目标描述/验收标准 |
| category | VARCHAR(20) | NOT NULL DEFAULT 'OTHER' | STUDY/FITNESS/LIFE/OTHER |
| deposit | INT | NOT NULL | 押金（币） |
| status | VARCHAR(20) | NOT NULL DEFAULT 'ACTIVE' | ACTIVE/VOTING/SUCCESS/FAILED |
| deadline | DATETIME | NOT NULL | 截止时间 |
| settled_at | DATETIME | NULL | 结算时间 |
| settle_result | VARCHAR(20) | NULL | 结算结果 SUCCESS/FAILED，与 status 冗余便于展示 |
| proof_content | VARCHAR(500) | NULL | 履约凭证文字 |
| proof_images | JSON | NULL | 凭证图片 URL 数组 |
| proof_submitted_at | DATETIME | NULL | 凭证提交时间 |
| view_count | INT | NOT NULL DEFAULT 0 | 围观数（Redis 定时落库） |
| is_deleted | TINYINT | NOT NULL DEFAULT 0 | 逻辑删除 |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

设计说明：

- 状态枚举用 VARCHAR 存字符串而非 TINYINT，演示和答辩时直观可读，MVP 阶段可接受
- **`(status, deadline)` 联合索引是定时任务的生命线**：到期扫描 `WHERE status='ACTIVE' AND deadline < NOW()` 必须走索引
- `settle_result` 为冗余字段，结算时与 status 同事务写入；如想精简可去掉，接口层直接映射 status

### 2.3 bet_contract_witness 见证人关联表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK | |
| contract_id | BIGINT UNSIGNED | NOT NULL | 合约 ID |
| user_id | BIGINT UNSIGNED | NOT NULL | 见证人用户 ID |
| accepted_at | DATETIME | NOT NULL | 接受邀请时间 |
| created_at | DATETIME | NOT NULL | |

约束与索引：

- `UNIQUE KEY uk_contract_user (contract_id, user_id)`：防重复见证
- `KEY idx_user (user_id)`：查"我见证的合约"

### 2.4 bet_vote 投票表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK | |
| contract_id | BIGINT UNSIGNED | NOT NULL | 合约 ID |
| user_id | BIGINT UNSIGNED | NOT NULL | 投票人（必须是该合约见证人，业务层校验） |
| verdict | VARCHAR(10) | NOT NULL | SUCCESS / FAIL |
| comment | VARCHAR(200) | NULL | 评语 |
| created_at | DATETIME | NOT NULL | 投票时间 |

约束与索引：

- `UNIQUE KEY uk_contract_user (contract_id, user_id)`：**一人一票的数据库兜底**，与 Redis 幂等键双保险
- `KEY idx_contract (contract_id)`：计票查询

### 2.5 acc_transaction 资金流水表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK | 流水号 |
| user_id | BIGINT UNSIGNED | NOT NULL | 用户 ID |
| contract_id | BIGINT UNSIGNED | NULL | 关联合约（GIFT 类型为 NULL） |
| type | VARCHAR(20) | NOT NULL | GIFT/FREEZE/UNFREEZE/DEDUCT |
| amount | INT | NOT NULL | 变动金额，统一存正数，方向由 type 决定 |
| balance_after | INT | NOT NULL | 变动后可用余额 |
| frozen_after | INT | NOT NULL | 变动后冻结金额 |
| remark | VARCHAR(100) | NULL | 摘要，如"创建合约冻结押金" |
| created_at | DATETIME | NOT NULL | |

设计说明：

- **只增不改**：流水表不提供 UPDATE/DELETE，是对账依据
- 金额统一正数 + type 表方向，避免正负号歧义（答辩时讲这个设计是加分点）
- `KEY idx_user_time (user_id, created_at)`、`KEY idx_contract (contract_id)`

### 2.6 sys_notification 通知表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT UNSIGNED | PK | |
| user_id | BIGINT UNSIGNED | NOT NULL | 接收人 |
| type | VARCHAR(30) | NOT NULL | WITNESS_INVITE/VERDICT_REQUEST/CONTRACT_SETTLED/WITNESS_ACCEPTED |
| title | VARCHAR(100) | NOT NULL | 通知文案 |
| contract_id | BIGINT UNSIGNED | NULL | 关联合约，前端跳转用 |
| is_read | TINYINT | NOT NULL DEFAULT 0 | 0 未读 1 已读 |
| created_at | DATETIME | NOT NULL | |

索引：`KEY idx_user_read (user_id, is_read)`（红点未读数高频查询）

## 3. 完整建表 SQL（MySQL 8.0）

```sql
CREATE DATABASE IF NOT EXISTS bet_platform
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE bet_platform;

CREATE TABLE sys_user (
  id         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  username   VARCHAR(20)  NOT NULL,
  password   VARCHAR(100) NOT NULL,
  nickname   VARCHAR(30)  NOT NULL,
  avatar     VARCHAR(255) NULL,
  balance    INT NOT NULL DEFAULT 1000 COMMENT '可用余额',
  frozen     INT NOT NULL DEFAULT 0    COMMENT '冻结金额',
  is_deleted TINYINT NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_username (username)
) ENGINE=InnoDB COMMENT='用户表';

CREATE TABLE bet_contract (
  id                 BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  user_id            BIGINT UNSIGNED NOT NULL,
  title              VARCHAR(50)  NOT NULL,
  description        VARCHAR(500) NULL,
  category           VARCHAR(20)  NOT NULL DEFAULT 'OTHER',
  deposit            INT NOT NULL COMMENT '押金',
  status             VARCHAR(20)  NOT NULL DEFAULT 'ACTIVE'
                     COMMENT 'ACTIVE/VOTING/SUCCESS/FAILED',
  deadline           DATETIME NOT NULL,
  settled_at         DATETIME NULL,
  settle_result      VARCHAR(20) NULL,
  proof_content      VARCHAR(500) NULL,
  proof_images       JSON NULL,
  proof_submitted_at DATETIME NULL,
  view_count         INT NOT NULL DEFAULT 0,
  is_deleted         TINYINT NOT NULL DEFAULT 0,
  created_at         DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at         DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_user (user_id),
  KEY idx_status_deadline (status, deadline),
  KEY idx_created (created_at)
) ENGINE=InnoDB COMMENT='对赌合约表';

CREATE TABLE bet_contract_witness (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  contract_id BIGINT UNSIGNED NOT NULL,
  user_id     BIGINT UNSIGNED NOT NULL,
  accepted_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_contract_user (contract_id, user_id),
  KEY idx_user (user_id)
) ENGINE=InnoDB COMMENT='合约见证人表';

CREATE TABLE bet_vote (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  contract_id BIGINT UNSIGNED NOT NULL,
  user_id     BIGINT UNSIGNED NOT NULL,
  verdict     VARCHAR(10) NOT NULL COMMENT 'SUCCESS/FAIL',
  comment     VARCHAR(200) NULL,
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_contract_user (contract_id, user_id),
  KEY idx_contract (contract_id)
) ENGINE=InnoDB COMMENT='见证人投票表';

CREATE TABLE acc_transaction (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  user_id       BIGINT UNSIGNED NOT NULL,
  contract_id   BIGINT UNSIGNED NULL,
  type          VARCHAR(20) NOT NULL COMMENT 'GIFT/FREEZE/UNFREEZE/DEDUCT',
  amount        INT NOT NULL COMMENT '变动金额，正数，方向由type决定',
  balance_after INT NOT NULL COMMENT '变动后可用余额',
  frozen_after  INT NOT NULL COMMENT '变动后冻结金额',
  remark        VARCHAR(100) NULL,
  created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_user_time (user_id, created_at),
  KEY idx_contract (contract_id)
) ENGINE=InnoDB COMMENT='资金流水表（只增不改）';

CREATE TABLE sys_notification (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  user_id     BIGINT UNSIGNED NOT NULL,
  type        VARCHAR(30)  NOT NULL,
  title       VARCHAR(100) NOT NULL,
  contract_id BIGINT UNSIGNED NULL,
  is_read     TINYINT NOT NULL DEFAULT 0,
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_user_read (user_id, is_read)
) ENGINE=InnoDB COMMENT='站内通知表';
```

## 4. 关键业务 SQL 与并发设计（重点）

### 4.1 状态机流转

```
ACTIVE ──到期扫描──> VOTING ──多数决SUCCESS──> SUCCESS
                          │
                          ├──多数决FAIL/平票──> FAILED
                          └──24小时无人投票───> FAILED
```

**所有状态变更必须用带原状态条件的 UPDATE**（乐观状态校验），利用影响行数判断是否成功：

```sql
-- 到期扫描流转，影响行数为 0 说明已被其他节点处理，直接跳过
UPDATE bet_contract
SET status = 'VOTING', updated_at = NOW()
WHERE id = #{id} AND status = 'ACTIVE' AND is_deleted = 0;

-- 结算流转同理
UPDATE bet_contract
SET status = #{result}, settle_result = #{result}, settled_at = NOW()
WHERE id = #{id} AND status = 'VOTING';
```

### 4.2 资金变动的原子 UPDATE

```sql
-- 创建合约冻结押金：余额够才冻结，影响行数 0 = 余额不足，抛业务异常
UPDATE sys_user
SET balance = balance - #{deposit},
    frozen  = frozen + #{deposit}
WHERE id = #{userId} AND balance >= #{deposit};

-- 履约成功解冻
UPDATE sys_user
SET balance = balance + #{deposit},
    frozen  = frozen - #{deposit}
WHERE id = #{userId} AND frozen >= #{deposit};

-- 违约扣款
UPDATE sys_user
SET frozen = frozen - #{deposit}
WHERE id = #{userId} AND frozen >= #{deposit};
```

**严禁**在 Java 代码里"先 SELECT 余额再 UPDATE"，高并发下必出超扣。每条资金 UPDATE 与流水 INSERT 必须在同一事务。

### 4.3 计票 SQL

```sql
SELECT verdict, COUNT(*) AS cnt
FROM bet_vote
WHERE contract_id = #{contractId}
GROUP BY verdict;
```

计票规则在 Java 层实现：SUCCESS > FAIL → 通过；全员已投且 SUCCESS ≤ FAIL → 失败；24 小时无人投票 → 失败。

### 4.4 诚信档案统计（不做冗余计数表，直接聚合）

```sql
SELECT
  COUNT(*) AS totalSettled,
  SUM(status = 'SUCCESS') AS successCount,
  SUM(status = 'FAILED')  AS failCount
FROM bet_contract
WHERE user_id = #{userId}
  AND status IN ('SUCCESS','FAILED')
  AND is_deleted = 0;
```

MVP 数据量小，实时聚合即可；履约率 = successCount / totalSettled，分母 0 时返回 null。二期可加统计冗余字段或物化视图。

## 5. MyBatis 落地建议

- **强烈建议用 MyBatis-Plus**：单表 CRUD 零 XML，`@TableLogic` 配逻辑删除，`BaseMapper` 直接省掉 80% 的 Mapper 代码，7 天排期里能省一天
- 只有以下场景手写 SQL（XML 或 `@Update` 注解均可）：
  - 4.1 / 4.2 的带条件原子 UPDATE
  - 4.3 计票聚合、4.4 档案聚合
  - 广场列表的多表联查（合约 + 创建者昵称 + 见证人数）
- 实体与表一一对应：`SysUser` / `BetContract` / `BetContractWitness` / `BetVote` / `AccTransaction` / `SysNotification`
- `proof_images` 为 JSON 类型，MyBatis-Plus 配 `JacksonTypeHandler` 映射为 `List<String>`
- 枚举（ContractStatus、Verdict、TransactionType、NotificationType）建 Java enum，数据库仍存字符串，用 `IEnum` 或 TypeHandler 转换

## 6. Redis 与 MySQL 的职责边界

| 数据 | 存储 | 原因 |
|---|---|---|
| 用户/合约/投票/流水/通知 | MySQL | 需要持久化、事务、对账 |
| 登录会话 token | Redis（Sa-Token 托管） | `sa-token-redis` 自动维护，TTL 过期与登出清除无需业务代码处理 |
| 见证邀请码 | Redis | 72 小时自然过期，无需清理任务 |
| 投票幂等键 | Redis | SETNX 防重复提交，DB 唯一索引兜底 |
| 结算分布式锁 | Redis | 多实例防并发结算 |
| 围观计数 | Redis 计数 + 定时落库 | 高频写不打 MySQL |

原则一句话：**要追责的钱和票全在 MySQL，要速度的临时状态全在 Redis。**
